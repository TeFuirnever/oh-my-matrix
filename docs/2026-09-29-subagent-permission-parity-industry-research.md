# Subagent Permission Parity — Industry Research

**Date**: 2026-09-29
**Purpose**: Backs the upstream issue draft `2026-09-29-omm-subagent-exec-command-classification-gaps.md`. A reviewer asked: *"subagent permissions and main-agent permissions are inconsistent — shouldn't they be consistent, per industry best practices?"* This note tests the repo's two-layer thesis against official vendor documentation only: **(1)** the verdict/classification layer must be session-agnostic (same command → same verdict regardless of who asks); **(2)** the stance layer is deliberately stricter for subagents (fail-closed, no interactive escalation) with an explicit operator-configurable expansion lever — i.e. effective subagent permission ⊆ main-session permission ∪ operator-granted extras. Sources: docs.claude.com / code.claude.com, learn.chatgpt.com (the redirect target of developers.openai.com/codex), and the google-gemini/gemini-cli and openai/codex repos. Every claim is labeled DOCUMENTED (verbatim quote + URL), INFERRED (reasoning from documented behavior), or UNVERIFIED.

---

## Verdict

**The evidence supports the two-layer principle — with two documented nuances that sharpen rather than refute it.** All four vendors converge on the same architecture: a single rule set (allow/deny/policy/sandbox rules) evaluates every tool call **regardless of which session issues it** — the verdict layer is session-agnostic (Claude Code: a `permissions.deny` Bash rule "applies to the main conversation and to subagents", and in auto mode "each of its actions goes through the classifier with the same rules as the parent session"; Codex: "Subagents inherit your current sandbox policy"; Gemini: "local sub-agent actions are executed silently and checked individually"). On top of that shared verdict layer, each vendor adds a **stance layer for delegated sessions**: no subagent can reach the vendor's maximum-privilege mode unless the parent already runs in it (Claude Code: "A subagent runs in `bypassPermissions` mode only when the main conversation does"; Codex subagents inherit "the permission mode selected beneath the composer"), and **non-interactive delegated sessions fail closed everywhere** (Claude Code `dontAsk` "never prompts" and headless auto mode "denies the command immediately"; Codex non-interactive: "an action that needs new approval fails"; Gemini: `ask_user` "in non-interactive mode, this is treated as `deny`"). The two nuances: **(a)** Claude Code and Codex both document operator-authored per-subagent *widening* (agent-file `permissionMode`/`sandbox_mode` overrides), so the strict claim "subagent stance ≤ parent stance" is not literally guaranteed — what is guaranteed is that every expansion is **operator-granted (authored config, folder trust, or a human answering a surfaced prompt), never agent-initiated**; **(b)** Claude Code *interactive* subagents do have an escalation path — prompts are "passed through to you as they come up" (foreground) or "surfaced ... in your main session" (background) — so fail-closed-without-human is specifically the **non-interactive** posture, which is exactly the posture of oh-my-matrix's host-driven subagent sessions. The reviewer's "shouldn't they be consistent" is answered by the industry itself: verdicts consistent, stances deliberately asymmetric, expansion operator-owned.

The one row where the thesis needs its stated nuance: **"inheritance direction"**. Both Claude Code and Codex document operator-authored widening (frontmatter `permissionMode`, per-agent `sandbox_mode`). The industry invariant is therefore not "subagent privilege ≤ parent privilege" but the weaker, still-load-bearing invariant: **subagent privilege ≤ (parent privilege ∪ operator-granted extras), and never agent-granted expansion** — plus the categorical rule that the top mode (`bypassPermissions` / `danger-full-access`) is parent-gated in both ecosystems.

## 6. Implications for oh-my-matrix

**Findings that back the current design (keep fail-closed stance + classification fixes + `subagentExtraAllowTools`):**

1. **Two layers are the industry norm, not a quirk.** Claude Code (rules + mode), Codex (sandbox + approval policy), Gemini (policy decisions + approval mode), and the Agent SDK (rules + `permissionMode`) all separate *what a call is* (rule evaluation, identical for parent and child) from *what happens on an unmatched call* (a per-session stance). oh-my-matrix's permission-policy (verdict) / dynamic-workflows (`defaultDeny` stance) split maps one-to-one.
2. **Fail-closed for non-interactive delegated sessions is documented behavior in all four stacks.** `dontAsk` ("denied"), Codex `never`/headless ("needs new approval fails"), Gemini `ask_user`→deny headless. oh-my-matrix's subagent sessions are host-driven and non-interactive, so keeping `defaultDeny: true` with `unknown` → block is the stance the industry documents for exactly that environment — not stricter than the ecosystem, but aligned with it.
3. **`subagentExtraAllowTools` is the analog of three documented operator levers**: Claude agent frontmatter `permissionMode`/`tools` (operator-authored, folder-trust gated), Codex per-agent TOML `sandbox_mode`, Gemini `subagent`-scoped policy rules. None of them let the *agent* widen anything; all are files/flags the operator writes. That is precisely the design of an operator config key — and the reason the escape hatch belongs in operator configuration rather than in classifier leniency.
4. **Issue A/B/C (classification fixes) are verdict-layer work and are stance-neutral.** The industry evidence says verdicts should be identical for main and subagent sessions — so fixing the PowerShell backtick false positive and adding interpreter/PowerShell-cmdlet families improves the subagent without loosening the main session's guard, exactly like a Claude Code `Bash(...)` deny rule that "applies to the main conversation and to subagents."
5. **The reviewer's premise is answered, not conceded**: no vendor makes subagent *stance* equal to main-agent stance. Codex documents the inheritance of the human's choice but routes every expansion through the human; Claude Code hard-gates `bypassPermissions`; Gemini scopes extra rules per caller as admin config. "Consistency" in industry practice lives in the verdict layer.

**Findings that challenge or bound the design (report honestly):**

6. **Claude Code does not guarantee subagent stance ≤ parent stance in interactive sessions** — a `plan`-mode parent can spawn an `acceptEdits` subagent via frontmatter. If oh-my-matrix ever claims strict containment as an invariant, it is claiming more than Claude Code does; the defensible claim is "⊆ parent ∪ operator extras, never agent-widened."
7. **Claude Code interactive subagents do escalate interactively** (prompts passed through / surfaced in the main session). oh-my-matrix's blanket no-escalation for subagents is *stricter* than Claude Code's interactive path — justified only by the non-interactive nature of its host sessions, which is a real difference today but should be stated as the reason in the upstream issue (the fail-closed stance cites the headless posture, per rows 1.5 / 2.8 / 3.3).
8. **Gemini's caller-differentiated rules (`subagent` field) show verdicts *can* legitimately differ by caller when the operator writes it that way.** This does not contradict session-agnostic *verdict logic* — the same engine evaluates every call — but it clarifies the principle: differentiation belongs in the operator-authored rule set, never in the runtime decision path of the classifier itself. oh-my-matrix's `classifyCommand` should stay caller-blind; `subagentExtraAllowTools` is where caller-difference lives.
